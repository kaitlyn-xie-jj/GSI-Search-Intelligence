# 开发约定

本页记录当前文档和代码维护中的基本约定。新增功能时，应优先保持模块边界和运行入口一致。

## 模块边界

- Planner 负责生成计划，不直接处理底层平台执行细节。
- Validator 负责检查计划和 state，不修改训练超参数。
- Solver 负责任务分配和优化，不承载 LLM prompt 逻辑。
- Platform 负责执行技能并返回反馈，不决定全局规划策略。
- Batch runner 负责运行批次和聚合指标，不应隐式改变任务语义。

## 配置优先级

运行脚本的 CLI 参数通常优先于 `config/default.json`。训练脚本中的显式环境变量优先于默认值。涉及模型服务、数据集路径和 solver 后端的配置，建议在运行命令中显式声明。

## 文档同步

修改以下内容时应同步更新文档：

- 公开脚本参数。
- 数据格式。
- 训练默认参数。
- 模型或数据集 repo id。
- validator / reward 语义。
- 输出目录结构和指标字段。

## 提交建议

将大改动拆分为可审核提交，例如文档结构、训练脚本、业务逻辑和上游代码同步。避免在同一提交中混合无关重构。
