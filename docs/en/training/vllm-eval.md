# vLLM Startup and GSI Evaluation

This page explains how to expose a model through vLLM as an OpenAI-compatible endpoint and call it from GSI benchmark or replan collection scripts.

Supported model forms:

- base/fresh model
- SFT LoRA adapter
- RLVR LoRA adapter
- merged full model

## Common Environment

Commands assume the training container:

```bash
cd /GSI
export VLLM_HOST=127.0.0.1
export VLLM_PORT=8001
export VLLM_GPU_MEMORY_UTILIZATION=0.75
export VLLM_MAX_NUM_SEQS=64
export VLLM_PREFLIGHT_HEADROOM_MB=1024
```

Check memory before startup:

```bash
CUDA_VISIBLE_DEVICES=0 ./llm_finetune/scripts/runtime/check_vllm_gpu.sh
```

If the current directory is `/GSI/llm_finetune`:

```bash
CUDA_VISIBLE_DEVICES=0 ./scripts/runtime/check_vllm_gpu.sh
```

## Hugging Face and Offline Mode

When `--model` uses a repo id, vLLM first reuses the container Hugging Face cache. If files are missing and network is available, it downloads them.

For local cache only:

```bash
export HF_HUB_OFFLINE=1
export TRANSFORMERS_OFFLINE=1
```

If `--model` is a local full model directory, these offline variables are usually unnecessary.

## Start a Full Model

Use this for base models, SFT merged models, RLVR merged models, or released full checkpoints.

Released RLVR model:

```bash
export SERVED_MODEL_NAME=qwen3_0_6b_cybertown_rlvr
export MODEL_PATH=WindyLab/Qwen3-0.6B-cybertown-RLVR
```

Local merged model:

```bash
export SERVED_MODEL_NAME=qwen3_0_6b_cybertown_sft
export MODEL_PATH=/GSI/outputs/sft/qwen3_0_6b_cybertown_sft_merged
```

Start:

```bash
CUDA_VISIBLE_DEVICES=0 python -m vllm.entrypoints.openai.api_server \
  --model "$MODEL_PATH" \
  --served-model-name "$SERVED_MODEL_NAME" \
  --host "${VLLM_HOST:-127.0.0.1}" \
  --port "${VLLM_PORT:-8001}" \
  --max-model-len 4096 \
  --max-num-seqs "$VLLM_MAX_NUM_SEQS" \
  --dtype bfloat16 \
  --gpu-memory-utilization "$VLLM_GPU_MEMORY_UTILIZATION" \
  --trust-remote-code \
  --no-enable-log-requests
```

## Start an SFT LoRA Adapter

Use this for `lora_adapters/` generated by `train_sft_unsloth.sh`:

```bash
export BASE_MODEL=Qwen/Qwen3-0.6B
export SFT_ADAPTER_DIR=/GSI/outputs/sft/qwen3_0_6b_cybertown_sft/lora_adapters
export SERVED_MODEL_NAME=qwen3_0_6b_cybertown_sft
```

```bash
CUDA_VISIBLE_DEVICES=0 python -m vllm.entrypoints.openai.api_server \
  --model "$BASE_MODEL" \
  --served-model-name qwen3_0_6b_base \
  --enable-lora \
  --lora-modules "${SERVED_MODEL_NAME}=${SFT_ADAPTER_DIR}" \
  --max-lora-rank 32 \
  --host "${VLLM_HOST:-127.0.0.1}" \
  --port "${VLLM_PORT:-8001}" \
  --max-model-len 4096 \
  --max-num-seqs "$VLLM_MAX_NUM_SEQS" \
  --dtype bfloat16 \
  --gpu-memory-utilization "$VLLM_GPU_MEMORY_UTILIZATION" \
  --trust-remote-code \
  --no-enable-log-requests
```

## Merge LoRA

```bash
python -m llm_finetune.sft.merge_lora \
  --base-model "$BASE_MODEL" \
  --adapter-path "$SFT_ADAPTER_DIR" \
  --output-dir /GSI/outputs/sft/qwen3_0_6b_cybertown_sft_merged
```

RLVR adapters can use the same command if `--base-model` points to the model used to train the adapter.

## Check the Service

After vLLM starts, the original terminal is occupied by the server. Open another container shell:

```bash
cd /path/to/GSI
docker compose -f docker/docker-compose.runtime-train.yml run --rm gsi-train bash
```

Check the model list:

```bash
curl -fsS http://127.0.0.1:8001/v1/models | python -m json.tool
```

Common startup issues:

- Port `8001` is already in use.
- `MODEL_PATH`, `BASE_MODEL`, or adapter directory does not exist.
- LoRA rank exceeds `--max-lora-rank`.
- `--max-model-len`, `--max-num-seqs`, or memory ratio is too high.

## Configure GSI

```bash
export GSI_LLM_API_BASE=http://127.0.0.1:8001/v1
export GSI_LLM_API_KEY=EMPTY
export GSI_LLM_MODEL=qwen3_0_6b_cybertown_sft
export GSI_DISABLE_TOKEN_STATS=1
export NO_PROXY=127.0.0.1,localhost,${NO_PROXY:-}
export no_proxy=127.0.0.1,localhost,${no_proxy:-}
```

`GSI_LLM_MODEL` must match the model name exposed by vLLM. In LoRA mode, this is the left side of `--lora-modules`; in full-model mode, it is `--served-model-name`.

Configure task allocation solver:

```bash
export GSI_TANGO_SOLVER_BACKEND=scip
export GSI_TANGO_SOLVER_MAX_TIME=120
```

## Prepare Benchmark Data

```bash
export GSI_DATASET_ROOT=$(
python - <<'PY'
from huggingface_hub import snapshot_download
print(snapshot_download(
    repo_id="WindyLab/GSI",
    repo_type="dataset",
    revision="small",
))
PY
)
```

Check:

```bash
find "$GSI_DATASET_ROOT" -maxdepth 5 \( -name tasks.jsonl -o -name goals.jsonl \) -print
```

## Collect Replan Data

```bash
python run/run_collect_replan_dataset.py \
  --batch-name eval_qwen3_0_6b_cybertown_nc4 \
  --output-root outputs/replan_collect \
  --dataset-root "$GSI_DATASET_ROOT" \
  --max-count 100 \
  --max-workers 10 \
  --max-newcases-per-run 4 \
  --capture-save-llm-io \
  --capture-max-records-per-run 4 \
  --capture-data-tag eval_qwen3_0_6b_cybertown_nc4
```

## Run Benchmark

Default SGI evaluation:

```bash
python run/run_exp_multi_method.py \
  --methods sgi \
  --enable-newcase \
  --newcase-counts 4 \
  --max-count 100 \
  --max-workers 10 \
  --dataset-root "$GSI_DATASET_ROOT" \
  --output-root outputs/eval_multi_method/qwen3_0_6b_cybertown
```

Base-model baseline comparison:

```bash
python run/run_exp_multi_method.py \
  --methods sgi spine smartllm lipllm \
  --enable-newcase \
  --newcase-counts 4 \
  --max-count 100 \
  --max-workers 10 \
  --dataset-root "$GSI_DATASET_ROOT" \
  --output-root outputs/eval_multi_method/qwen3_0_6b_cybertown_baselines
```

## Inspect Results

Output is usually under:

```text
outputs/eval_multi_method/qwen3_0_6b_cybertown/<timestamp>/newcase_*/batch_<method>/
```

Read `aggregate_full.json` first, then use `summary.jsonl` and single-task directories to analyze failures. Field descriptions are in [Output Directory](outputs.md).
